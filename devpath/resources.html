Start here

Your first seven days.

About one hour a day. By day seven you'll have a live URL and a habit. Do this before you open the roadmap.

Day 01

Set up the bench

Install a Chromium browser and VS Code. Open DevTools on three sites you use daily and click through Network and Elements until they stop being intimidating.

Day 02

Trace one page load

Stage 1, lesson 1. Write down every request one page makes and what each status code meant. Twenty minutes of this explains more than a week of videos.

Day 03

Write HTML by hand

A page about something you actually like: a heading, two sections, a list, an image with real alt text, one link. No CSS yet.

Day 04

Make it not ugly

One typeface, one accent colour, a spacing scale of four values. Style with classes, not element selectors. This is 80% of looking designed.

Day 05

Make it work on a phone

Resize the window from 360px to 1440px and fix every overflow, tap target under 44px, and line that becomes unreadable.

Day 06

Put it on the internet

git init, first commit, push to GitHub, turn on Pages. Read the live URL on your phone, on mobile data, not wifi.

Day 07

Send it to a human

One person. Ask what they think it is and what confused them. Their answer is your first real feedback loop — write it down.

When you're stuck

A protocol, so being stuck doesn't become quitting.

Every working developer runs a version of this. It's the highest-leverage skill in the whole path.

1. Shrink it

Delete code until the problem is reproducible in ten lines. Nine times out of ten the bug reveals itself during the deletion.

2. Read the error, out loud

Bottom line first — that's the actual error; the lines above are the path to it. Say the message out loud and your brain stops skipping the important noun.

3. Search the exact message

Strip your own variable names, keep the quotes. Add the library and its version. Read the two closest results before clicking anything else.

4. Read the docs for the thing

Not a tutorial about it — the page for the function you're actually calling. Check the parameters and the return value you assumed.

5. Write the question

Code, expected, actual, what you tried. Half the time writing it produces the answer; if not, you now have a question people can actually answer.

6. Then ask

A specific question in a real community — a Discord for the framework, a subreddit, a colleague. "It doesn't work" gets ignored; the write-up from step five gets answered.
